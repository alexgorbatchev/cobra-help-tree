# cobra-help-tree

Reusable Go library for rendering nested Cobra CLI command hierarchies as clean, aligned ASCII trees in terminal help screens.

## Commands
- **Run Tests:** `just test` (`go test -v -cover ./...`)
- **Run Everything CI Runs:** `just check` (`just lint` then `just coverage`)
- **Enforce the Coverage Floor:** `just coverage` — runs every package's tests under `-race`, measures the library packages only (`-coverpkg`, so an example cannot dilute the number), and exits non-zero below `min_coverage` (90). CI runs the same recipe
- **Preview the Rendered Help:** `just run <args>` and `just run-ai <args>` (e.g. `just run user create --help`), which drive `examples/demo`
- **Run Linter:** `just lint` — `gofmt -l` must be empty, then `go vet ./...`, then `go mod tidy -diff`
- **Format Source Code:** `just fmt` (`go fmt ./...`)

## Setup & Environment
- **Prerequisites:** Go 1.26+, `just`.
- **Dependencies:** `github.com/spf13/cobra`, `github.com/spf13/pflag`, `github.com/mattn/go-runewidth`, `golang.org/x/term`.
- **Module Path:** the module is `github.com/alexgorbatchev/cobra-help-tree/v2`. Go requires the major-version suffix from v2 onward, so a `v2.x.y` tag is only importable with the `/v2` path; bumping to v3 means changing `go.mod`, every internal import, and the README together.
- **Layout:** one library package at the repository root, plus `examples/demo`, a runnable CLI that renders the README's command hierarchy. The example is the target of `just run` and `just run-ai`; keep it compiling, because it is the only executable proof the documented screens are real.
- **Files:** one concern per file, each with a test file of the same name. `doc.go` (package documentation), `options.go` (`TreeOptions`, `AgentOptions`, `HelpOptions` and their validation), `catalog.go` (`ArgSpec`, `EnvSpec`, `QuickstartItem`, `TechInfo`, `TechCatalog`), `column.go` (the two-column alignment engine every block renders through), `tree.go` (tree walking and subcommand visibility), `help.go` (human help and usage screens), `agent.go` (`AGENT=1` screen and line clipping), `skill.go` (the `skill` command, the agent alert, and `SkillOmissions`), `terminal.go` (mode and width detection), `setup.go` (the cobra installation). Shared test fixtures and helpers live in `helpers_test.go`, and `examples/demo` carries its own tests so a broken example fails CI rather than the next reader. Put a new declaration in the file that owns its concern rather than growing one file.

## Conventions
- **ASCII Tree Rendering:** Uses Unicode box-drawing branches (`├─ `, `╰─ `, `│  `) with single-line aligned descriptions.
- **Display Cell Width:** Measure and truncate by terminal cells with `runewidth.StringWidth` and `runewidth.Truncate`, never `utf8.RuneCountInString` or rune slicing. A CJK ideograph or emoji is one rune in two cells, so rune counts break column alignment and overrun the width limit.
- **Terminal Width Handling:** Automatically detects terminal width via `golang.org/x/term` / `$COLUMNS`, truncating command and argument descriptions with `...` and wrapping flag descriptions before line overflow occurs.
- **Requested Help Goes to Stdout:** Render help via `c.OutOrStdout()`. Cobra's `c.Print` falls back to **stderr**, which silently breaks `--help | less` and `--help > file`.
- **Deterministic Agent Output:** `AGENT=1` output must be byte-identical across runs. Sort any map before emitting it, and nest caller-supplied maps such as `TechInfo.Metadata` under their own key so they cannot collide with reserved top-level keys.
- **No Optional Variadic Parameters:** Exported functions take explicit parameters. Optional configuration gets a second named function (`Setup` / `SetupWithOptions`), never `opts ...TreeOptions`, which compiles fine while silently discarding every argument past the first.
- **Zero-Value Options:** `TreeOptions.resolve()` supplies the fallback for every unset sizing field, which is what makes `TreeOptions{}` a fully configured value. Add new sizing defaults as constants consumed by `resolve()`; never inline a literal such as `if widest < 20` into the render path.
- **One Call Replaces Both Cobra Screens:** Cobra prints `--help` through `HelpFunc` but prints the screen following a flag or argument error through `UsageFunc`, via `UsageString` (`command.go:1166`). `SetupWithOptions` installs both, so a consumer never gets a tree on `--help` and cobra's flat command list on an error. Both funcs are inherited by descendants, so installing on the root is enough. Keep the split mirroring cobra's own: `RenderTreeHelp` is the long description plus `RenderTreeUsage`, and `RenderTreeUsage` never repeats the description. Agent mode has a single screen for both, because the two differ only in visual framing and a machine reader wants one format.
- **Arguments and Environment Variables Come From The Catalog:** Cobra has no field describing a positional argument or environment variable. `Use` carries argument names as free text and `ValidArgs` is the enum of accepted values for the *first* positional argument (`args.go`, `OnlyValidArgs`), so `TechInfo.Args` and `TechInfo.Env` are the only sources for per-argument and per-env descriptions. Report `ValidArgs` under `valid_args:`, never as `args:`, and split the description cobra packs behind a tab (`cobra.CompletionWithDesc`) rather than emitting a control character inside a value. `ArgSpec.Name` renders verbatim: the library cannot know whether an argument is required, optional or variadic, so it never adds brackets of its own. `TechInfo.Quickstart` supplies command examples with aligned inline comments.
- **Catalog Is Content, Options Are Formatting:** `TechCatalog` is a parameter of the renderers rather than a field of `TreeOptions` or `AgentOptions`, because both modes render its arguments and the options structs stay mode-specific. `HelpOptions.Catalog` carries it for `Setup`.
- **Match Cobra's Defaults, Always:** Where cobra has a default behaviour, this library's default must be the same one, and any deviation has to be narrow, commented with its reason, and locked by a test. Delegate to cobra's own predicate rather than reimplementing it: a hand-rolled equivalent drifts from upstream silently, which is how deprecated commands once stayed listed here after cobra had started hiding them.
- **One Visibility Rule For Every Renderer:** `visibleSubcommands` is the only place a child command is judged fit for help, so the tree, the agent-mode subcommand list and the `[command]` suffix on the usage line cannot disagree. Availability is cobra's `Command.IsAvailableCommand`, which drops hidden commands, deprecated commands, the generated help command, and any command that is neither runnable nor the parent of a runnable one. Nothing is filtered on top of it by default, so the default screen lists what cobra's own help lists. `TestRenderersAgreeOnVisibleSubcommands` locks all three surfaces at once.
- **Every Screen Lists The Whole Subtree:** The human tree and the agent `subcommands:` list both recurse, because one request for help has to describe everything below the command; an agent shown only the next level needs a further call per group. `agentSubcommands` nests each group's commands one `agentListIndent` deeper, and each entry is the command's `Use`, so it carries the arguments its branch in the tree shows. Do not shorten the agent list to direct children to save tokens. `TestRenderersAgreeOnVisibleSubcommands` and `TestRenderAgentHelpListsTheWholeSubtree` lock it.
- **The Skill Is A Command In The Tree, And The Alert Follows It:** `HelpOptions.Skill` makes `SetupWithOptions` add the `skill` command to the root with `AddCommand`, so cobra lists, completes and parses it like any other. `skillAlert` prints the alert for any command whose root carries a child marked with `skillAnnotation`; it reads the tree, never the option, so the alert cannot name a command the binary lacks, and a CLI's own command that is merely called `skill` gets no alert. The alert is joined on after `clipLines`, because a clipped alert cuts the command it names. Keep its wording exactly ``ALERT: Agents must read `AGENT=1 <cli> skill` before using this tool.``, which `cli-best-practices` fixes.
- **The Skill Prints Verbatim:** The `skill` command writes the string it was given to `c.OutOrStdout()` unchanged in both modes: no alert, no trimming, no added newline. It takes no arguments, defines no flags, and returns a failed write as its error. `SetupWithOptions` rejects a non-root command and a root that already has a command named or aliased `skill` before it installs anything.
- **`SkillOmissions` Compares Names As Whole Words, And Flags Line By Line:** It reports command paths, flags, shorthands, and the catalog's arguments and environment variables that the skill text lacks. `mentionsWord` accepts a name only where no letter, digit, `-` or `_` touches it, so `-c` is not found inside `--config`. For a flag the skill does name, some line naming it must state its type (`f.Value.Type()`, any letter case) and, when `hasNonZeroDefault` says it has one, its default (`f.DefValue`), both as whole words; a flag named nowhere is one omission, not three. It walks what help lists plus cobra's generated `help` command, which `isGeneratedHelpCommand` identifies without a name test, and it calls cobra's `InitDefault*` functions first because an unexecuted tree lacks the generated commands and flags. It reads lines, never Markdown structure, and judges nothing beyond those names and values; do not grow it into a parser of the document.
- **The Demo Carries A Complete Skill:** `examples/demo/SKILL.md` is embedded and passed as `Skill`, and `TestDemoSkillCoversTheWholeInterface` fails when it omits anything. Update that file in the same change as the demo's commands, flags or catalog.
- **Hiding Generated Commands Is Opt-In and Aimed:** `TreeOptions.HideGeneratedCommands` drops the commands the CLI did not define from the human screens: the generated `completion` command with its shell subtree, and the `skill` command, which `isSkillCommand` recognises by its annotation and never by its name. The zero value keeps them, because cobra lists `completion` and the binary accepts both. The filter matches a command named `completion` **directly under the root**, the only place `InitDefaultCompletionCmd` adds one (it returns early when a root child already uses that name or alias), so a CLI's own nested `completion` command is never hidden. Do not extend this to `help`: cobra's predicate already excludes the generated help command by identity, and a command named `help` that survives that check belongs to the CLI. The option is human-mode formatting, so `RenderAgentHelp` never applies it — agent output describes the interface the binary accepts, and `completion` is part of it.
- **A Deprecated Command Announces Itself On Its Own Screen:** Cobra keeps a deprecated command out of every listing and prints `Deprecated` only once the command runs, which leaves a user who still has it scripted with no warning until then. Both renderers therefore surface `cmd.Deprecated` on that command's own screen — `Deprecated: <message>` above the usage block, `deprecated: <message>` in agent mode — using the caller's wording, as cobra does. This adds information about the rendered command; it never changes which commands are listed.
- **Fixture Leaves Need a `Run`:** A leaf command with no `Run` is not an available command to cobra, so it renders nowhere. Test fixtures build leaves through `leafCommand`, which supplies one; a bare `&cobra.Command{Use: ..., Short: ...}` leaf silently disappears from every screen under test.
- **One Description Column Per Screen:** `descStartColumn` measures every block on a screen in one call and `renderLabelRows` renders each against that column, so the arguments block lines up with the command tree. A new block joins the same call; never give a block its own width, and never re-implement the padding or the ellipsis clipping.
- **No Exported Mutable Package State:** Defaults live in unexported constants, never in an exported `var`. An exported `var DefaultOptions` let any caller or goroutine reassign the library's defaults process-wide and have it leak into unrelated `Setup` calls.
- **Validate, Do Not Coerce:** Zero means "use the default" for every sizing field, but a negative value or a nil command is a caller mistake. `Validate` reports the former, `SetupWithOptions` reports both, and neither entry point installs anything on failure. Both `Setup` and `SetupWithOptions` return `error`; the string renderers stay total and return `""` for a nil command, because empty output is a well-defined result for a pure function while a failed install is not.
- **Options Match Their Renderer:** `TreeOptions` is what `FormatCommandTree`, `RenderTreeHelp` and `RenderTreeUsage` accept; `AgentOptions` is what `RenderAgentHelp` accepts. `HelpOptions` composes them and exists only for `Setup`, the one caller spanning both modes. Do not add a field to `TreeOptions` that only agent mode reads, or vice versa; anything both modes read is a parameter, as `TechCatalog` is.
- **Agent Flags State Only Defaults That Are Set:** An agent flag line ends in `(default: "…")` only when `hasNonZeroDefault` is true. That function asks pflag, by rendering a probe copy of the flag and looking for the `(default ` pflag prints, because `defaultIsZeroValue` is unexported and switches on unexported value types; do not replace it with a table of zero values, which would drift from pflag. The probe clears `Usage`, `Hidden` and `Deprecated`: a usage text can contain the words, and the other two keep a flag out of the rendering.
- **One Usage Line For Both Modes:** `usageLine` appends `[command]` to cobra's `UseLine` when the command has subcommands to list, and both `RenderTreeUsage` and `RenderAgentHelp` call it, so the two screens state the same syntax. Agent mode passes `hideGenerated` as false. Call it after the flags are read, for the reason given under **Never Read `cmd.Flags()` Directly**.
- **The Closing Hint Wraps, The Rest Clips:** Descriptions are clipped with an ellipsis because a wrapped one breaks the column. The closing `Use "… --help"` line is a sentence whose end is the instruction, so `wrapWords` breaks it between words at the terminal width and never inside a word. An unknown width leaves it on one line.
- **Agent Output Stays Untruncated by Default:** `cli-best-practices` requires full untruncated content under `AGENT=1`, so agent mode never consults `$COLUMNS` or the terminal size. `AgentOptions.MaxLineWidth` is opt-in and defaults to unlimited. `TestRenderAgentHelpIsUnclippedByDefault` guards this; do not "fix" it by wiring `GetTerminalWidth` into `RenderAgentHelp`.
- **Renderers Mutate and Are Not Concurrency-Safe:** Reading a command's flags makes cobra merge persistent flag sets, and `updateParentsPflags` writes to the **root and every ancestor**, not the command being rendered. Two goroutines rendering sibling subcommands race inside cobra; `go test -race` reproduces it. `Setup` users are unaffected because cobra executes single-threaded. This is documented in the package comment; do not paper over it with a package mutex, which cannot cover cobra's own `Execute`.
- **Do Not Filter pflag Globals From Help:** cobra folds `pflag.CommandLine` into every root's persistent flags (`command.go:1918`), so a flag registered via package-level `pflag.String` and friends really is accepted by the binary — verified by running it. Help must list it; hiding it would document an interface the CLI does not have. `TestRenderersReportPflagGlobals` locks this. Note this is pflag's global set, never the standard library's `flag` package, which cobra does not consult.
- **Never Read `cmd.Flags()` Directly:** Cobra folds persistent and inherited flags into it only via `mergePersistentFlags`, which runs during `Execute` and inside `LocalFlags`/`InheritedFlags`. Reading `Flags()` drops them on any command not yet executed. Use `applicableFlags`, and call it **before** `cmd.UseLine()`: the merge flips `HasAvailableFlags`, so collecting flags afterwards makes the first render differ from every later one. This binds **both** renderers. `RenderTreeUsage` reads `LocalFlags()` and `InheritedFlags()` at the top for the same reason, not where the Flags sections are written; `TestRenderTreeUsageOmitsTheLongDescription` catches a regression because the help and usage screens then disagree on `[flags]`.
- **Clipped Agent Output Must Still Parse:** `clipLine` shortens only the value half of a `key: value` line, never a block opener such as `metadata:`, and returns a line in full when its key leaves no room for a readable value. `MaxLineWidth` is a ceiling, not a guarantee, because a truncated key is unidentifiable and may collide with another key.
- **Hermetic Unit Tests:** All unit tests must remain offline, hermetic, and deterministic.

## Gotchas
- **`cmd.SetOut` masks stream bugs in tests.** Cobra's `getOut` returns the writer installed by `SetOut` for *both* `OutOrStdout()` and `OutOrStderr()`, so a test using `SetOut(buf)` passes no matter which stream the code targets. Tests covering stream choice must replace `os.Stdout` / `os.Stderr` with `os.Pipe()`; see `captureStdio` in `tree_test.go`.
- **A pipe is not a terminal.** `GetTerminalWidth` falls back to `term.GetSize(os.Stdout.Fd())`, which fails under `go test`. Tests asserting the fallback must pin `os.Stdout` to a pipe; see `withNonTerminalStdout` in `tree_test.go`.

## Boundaries
- **Always:** Maintain >= 90% statement code coverage across the library packages. `just coverage` enforces it and CI runs the same recipe, so a drop fails the build rather than the review. The floor lives in the `min_coverage` variable at the top of the `justfile`; raise it rather than working around it. Main packages are excluded from the measurement, though their tests still run.
- **Always:** Run `just check` before committing changes — `just lint` covers formatting, vet and module hygiene but not the tests or the coverage floor.
- **Always:** Change a test file whenever a code change alters runtime output, and develop red/green — confirm the new test fails before the fix and passes after.
- **Never:** Publish releases, tags, packages, or deployments without explicit user authorization.
